# Baton

终端里的 agent 调度管理层：一个面向用户的管控 agent 负责对话与决策，把任务分派给职能 agent 执行；所有 agent 通过共识库 tool 按需查询组织级事实，不往上下文里硬塞知识。

Baton 不实现 agent 本体，复用现成的 CLI agent（pi、claude、codex 等）与 Orca worker 作为执行体，只负责「谁来做、何时做、做完向谁汇报、共识从哪查」。

## 核心约束

1. 用户只面对一个 agent，下级节点的提问沿汇报链上抛到根节点。
2. 共识不进 context，只通过 tool 查询。
3. 调度层与执行体解耦，换 agent 只加适配器。
4. 保持小，不为未来场景预留抽象。
5. 本地优先，不依赖远程服务。

## 当前状态

立项阶段（M0），尚无可运行代码。实现语言、TUI 栈、共识库形态在技术方案阶段决定。
